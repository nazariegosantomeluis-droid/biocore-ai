# Biomedical Signal Visualizer

A modular, research-ready ECG analysis and arrhythmia detection system using explainable AI. Designed for educational use and clinical support in cardiovascular assessment.

## Overview

This project implements a **computational cardiology pipeline** that combines:
- **Signal Processing**: ECG filtering, R-peak detection, RR interval computation
- **Feature Extraction**: Temporal, frequency-domain, and nonlinear HRV features
- **Machine Learning**: Binary classification (normal vs. arrhythmia) using Logistic Regression
- **Explainable AI**: Physiological interpretation of predictions for medical students and clinicians
- **Medical Education**: Interactive tutor explaining ECG vs. PPG, waveform components, and adaptive quizzes.

## 🛡️ Software Quality Standards
This project follows industry-standard engineering practices:
- **SOLID Principles**: Decoupled modules for signal processing, AI, and UI.
- **Modular Architecture**: Layered design separating domain logic from external interfaces.
- **Type Safety**: Full type hints for better maintainability.
- **Documentation**: Comprehensive docstrings and logging across the core engine.

## Features

### 🎓 Medical Education Engine
The platform provides automatic clinical explanations:
- **What is ECG?**: Measures the electrical potential generated by the heart's depolarization/repolarization.
- **What is PPG?**: An optical technique detecting blood volume changes in the microvascular bed (hemodynamic).
- **ECG vs PPG**: 
  - *ECG* is the gold standard for rhythm and conduction defects (electrical).
  - *PPG* is ideal for peripheral monitoring and oxygen saturation (mechanical/optical).
- **Waveform Representation**: Automatic breakdown of P, QRS, and T waves for ECG, and systolic/diastolic peaks for PPG.
- **Adaptive Quizzes**: AI-generated questions that adjust difficulty based on student performance.

### 0. Interactive Dashboard (Streamlit)
- **Multisensor Panel**: Correlates multiple vital signs in real-time.
- **Patient Management**: Clinical tracking with AI risk scoring.
- **AI Interpretability**: Detailed breakdown of why a model reached a conclusion.
- **Adaptive Education**: ECG Tutor with machine-learning based difficulty adjustment.

### 1. Signal Processing
- **R-Peak Detection**: Adaptive peak detection with distance constraints
- **RR Interval Computation**: Beat-to-beat timing for HRV analysis

### 2. Heart Rate Variability (HRV) Features

#### Temporal Domain
- **BPM**: Heart rate (beats per minute)
  - Normal: 60-100 bpm
  - Tachycardia: >100 bpm
  - Bradycardia: <60 bpm

- **SDNN**: Standard deviation of RR intervals (overall HRV)
  - Reflects total autonomic nervous system activity
  - Low SDNN associated with mortality risk

- **RMSSD**: Root mean square of successive differences
  - Measures parasympathetic (vagal) activity
  - High RMSSD indicates good cardioprotection

#### Frequency Domain
- **LF Power** (0.04-0.15 Hz): Low frequency, sympathetic activity
- **HF Power** (0.15-0.4 Hz): High frequency, parasympathetic activity
- **LF/HF Ratio**: Sympathetic-parasympathetic balance
  - <1: Parasympathetic dominance (healthy)
  - 1-2: Balanced autonomic tone
  - >3: Sympathetic dominance (stress, arrhythmia risk)

#### Nonlinear Features

### 3. Advanced Patient Analytics
- **Risk Predictor**: Weighted ML scoring for cardiovascular risk.
- **Anomaly Detector**: Z-score statistical analysis for real-time vital sign monitoring.
- **Health Index**: Composite score derived from multi-sensor data fusion.

### 3. Machine Learning Classification
- **Classes**: 
  - 0: Normal sinus rhythm
  - 1: Abnormal (arrhythmia)
- **Metrics**: Accuracy, Precision, Recall, F1-Score, ROC-AUC
- **Class Balancing**: Stratified train/test split

### 4. Explainable AI Interpretations

The system explains predictions in clinical terms:

```

Common in: anxiety, fever, arrhythmias, thyroid disorders, cardiac stress.
```

### Live EMG (Hardware)

The app provides a basic EMG streamer (`hardware/emg_stream.py`) which can connect to a serial device (ESP32 or similar) that streams timestamped samples. If `pyserial` is not available or no device is found, the streamer falls back to a simulation mode so the UI remains functional.

To stream from a microcontroller, ensure it outputs lines with either `timestamp,value` or `value` per line over serial at the chosen baud rate.

```
115.123,512
115.124,520
115.125,498
```

The EMG page also offers a demo generator and CSV upload to analyze activation (MRV), median frequency and a fatigue index.

### Hardware Firmware Example (ESP32 / Arduino)

Example minimal Arduino/ESP32 sketch that prints `timestamp,value` lines over serial (ADC values):

```cpp
// Minimal ESP32 example (Arduino)
#include <Arduino.h>

const int adcPin = 34; // ADC input

void setup() {
  Serial.begin(115200);
  delay(1000);
}

void loop() {
  unsigned long t = millis();
  int raw = analogRead(adcPin); // 0-4095 on ESP32
  Serial.printf("%lu, %d\n", t, raw);
  delay(1); // ~1000 Hz sample rate (approx)
}
```

Notes:
- Adjust `adcPin` and `delay()` to match your sampling rate and hardware.
- The app accepts either `timestamp,value` lines or plain numeric values per line.
- If you prefer to send only values, the streamer will assign local timestamps.

Advanced example (ESP32): timestamps in microseconds and scaled voltage output

```cpp
// ESP32 advanced example (Arduino)
#include <Arduino.h>

const int adcPin = 34; // ADC input
const float vref = 3.3f; // reference voltage

void setup() {
  Serial.begin(115200);
  delay(1000);
}

void loop() {
  uint64_t us = esp_timer_get_time(); // microsecond timestamp
  int raw = analogRead(adcPin); // 0-4095 on ESP32
  float volts = (raw / 4095.0) * vref;
  // send: timestamp_us,volts
  Serial.printf("%llu,%.6f\n", us, volts);
  delayMicroseconds(1000); // ~1000 Hz
}
```

This sketch uses `esp_timer_get_time()` for precise microsecond timestamps and sends floating voltage values; the app will accept these lines and use the timestamp provided.

- Requires adequate signal quality (SNR >10 dB)
